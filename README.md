# Ноготочки

Веб-сервис записи в бьюти-студию: клиент сам выбирает мастера и время,
администратор ведёт расписание в единой панели вместо звонков и переписки.

Учебный проект. Паспорт продукта — в [CLAUDE.md](CLAUDE.md).

**Что готово:** база данных и HTTP API — 73 эндпоинта, 21 таблица, 7 миграций,
18 наборов проверок (857 проверок).
**Чего нет:** фронтенда. Экраны нарисованы в виде прототипа
(папка [`Design_site`](Design_site)), вёрстки нет. API сейчас смотрят через
`curl`, браузерный клиент или `npm test`.

## Что нужно установить

Одна программа — **Node.js версии 24**. Больше ничего: базой служит SQLite,
встроенный в сам Node, а внешних библиотек у проекта нет, поэтому
**`npm install` выполнять не нужно** — устанавливать нечего.

Проверьте, что у вас уже есть:

```bash
node --version
```

Если команда не найдена или показывает версию ниже `23.4.0` — поставьте Node 24.

<details>
<summary>Как поставить Node 24</summary>

**macOS и Linux** — через [nvm](https://github.com/nvm-sh/nvm) (менеджер версий,
не требует прав администратора):

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
```

Затем **закройте терминал и откройте заново** и выполните:

```bash
nvm install 24 && nvm use 24
```

Нужная версия записана в файле `server/.nvmrc`, поэтому в дальнейшем
достаточно выполнить `nvm use` **из папки `server`** — версия подхватится сама.

**Windows** — скачайте установщик LTS с [nodejs.org](https://nodejs.org/)
и пройдите мастер установки.

Команды `npm ...` и `git ...` в PowerShell работают как есть. А вот примеры
с `curl`, `grep` и `PORT=3001 npm start` написаны для bash: в PowerShell
`curl` — это псевдоним другой команды со своим синтаксисом, `grep` нет вовсе,
а переменная окружения задаётся иначе (`$env:PORT=3001; npm start`).
Где это важно, ниже приведён вариант для PowerShell.

**Почему именно 24.** Проект использует встроенный модуль `node:sqlite`.
До версии 22.5 его нет вовсе, в 22.5–23.3 он требует отдельного флага,
без флага работает начиная с 23.4. Версия 24 — текущая LTS, её и ставим.
Если версия окажется неподходящей, проект не запустится молча: он объяснит,
что делать.

</details>

## Запуск

```bash
git clone https://github.com/alias1969/nogotochki.git
cd nogotochki/server
npm run env:init
npm run migrate
npm run seed
```

Затем запустите сервис:

```bash
npm start
```

В терминале появится:

```
Ноготочки: API слушает http://localhost:3000 (development)
```

Проверьте, что он отвечает, — в другом окне терминала:

```bash
curl http://localhost:3000/api/health
```

Ожидаемый ответ: `{"status":"ok","time":"..."}`.

Остановить сервис — `Ctrl+C` в окне, где он запущен.

### Что делает каждая команда

| Команда | Что происходит |
|---|---|
| `npm run env:init` | Создаёт файл `server/.env` и **генерирует секреты**: ключ подписи сессий, «перец» для паролей и пароли демонстрационных аккаунтов. В репозиторий этот файл не попадает. |
| `npm run migrate` | Создаёт файл базы `server/data/nogotochki.db` и её структуру — 21 таблицу, 30 индексов, триггеры. |
| `npm run seed` | Наполняет базу связным набором данных: три роли, два мастера с графиками, пять услуг, несколько записей на ближайшие дни. В продакшене не запускается. |
| `npm start` | Поднимает HTTP-сервер на порту 3000. |

## Как войти

Демонстрационные аккаунты создаёт `npm run seed`. **Паролей нет в коде** —
они случайные и лежат в файле `.env`. Посмотреть (находясь в папке `server`):

```bash
grep SEED_ .env
```

В PowerShell:

```powershell
Select-String SEED_ .env
```

Ищем по `SEED_`, а не по `PASSWORD`: в файле есть ещё `PASSWORD_PEPPER` —
это не пароль для входа, а секрет, которым «солится» хеширование.

| Кто | E-mail | Пароль из переменной |
|---|---|---|
| Администратор | `admin@nogotochki.local` | `SEED_ADMIN_PASSWORD` |
| Мастер Ольга | `olga@nogotochki.local` | `SEED_MASTER_PASSWORD` |
| Мастер Ирина | `irina@nogotochki.local` | `SEED_MASTER_PASSWORD` |
| Клиент Анна | `anna@example.com` | `SEED_CLIENT_PASSWORD` |

Пример входа через `curl` (подставьте свой пароль):

```bash
curl -X POST http://localhost:3000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@nogotochki.local","password":"ВАШ_ПАРОЛЬ_ИЗ_ENV"}'
```

В ответе придёт `token`. Дальше его передают заголовком:

```bash
curl http://localhost:3000/api/auth/me -H 'Authorization: Bearer ВАШ_ТОКЕН'
```

Витрина открыта без входа — попробуйте прямо сейчас:

```bash
curl http://localhost:3000/api/services
curl http://localhost:3000/api/masters
```

## Проверки

Набор проверок ходит по живому API, поэтому **сервис должен быть запущен**.
Нужно два окна терминала.

Окно 1:

```bash
cd nogotochki/server
npm start
```

Окно 2:

```bash
cd nogotochki/server
npm test
```

Ожидаемый итог — 18 блоков со строкой `Итого: N пройдено, 0 провалено`.

Отдельный набор запускается своей командой, например `npm run test:roles`
или `npm run test:hardening`. Полный список — в `package.json`.

> Проверки пишут в ту же базу, что и сервис: гоняйте их на базе для
> разработки, не на рабочей. Часть тестовых аккаунтов остаётся в базе —
> это ожидаемо, чистится командой `npm run db:reset`.

---

## Полезные команды

Все выполняются из папки `server`.

| Команда | Назначение |
|---|---|
| `npm start` | Запустить сервис |
| `npm run dev` | То же, с перезапуском при правке файлов |
| `npm test` | Все проверки (нужен запущенный сервис) |
| `npm run migrate` | Применить новые миграции |
| `npm run seed` | Долить тестовые данные (повторный запуск не плодит дубли) |
| `npm run db:reset` | Удалить базу и собрать заново с нуля |
| `npm run db:verify` | Сверить фактическую базу с документом схемы |
| `npm run db:describe` | Показать структуру базы: таблицы, поля, индексы |
| `npm run env:init` | Создать `.env` (существующий не трогает) |

## Настройки

Разделены по тому, **кто вправе их менять**.

**Настройки студии** — название, адрес, телефон, часовой пояс, длительность
резерва, горизонт записи, срок отмены, лимит переносов — лежат **в базе**
и меняются администратором через API (`PATCH /api/admin/settings`).
Трогать файлы на сервере для этого не нужно.

**Настройки среды и секреты** — порт, путь к базе, ключи, лимиты частоты
запросов — лежат в `server/.env`. Все переменные с пояснениями перечислены
в [`server/.env.example`](server/.env.example).

Файл `.env` в репозиторий не попадает и не должен: в нём настоящие секреты.
Именно поэтому его создаёт `npm run env:init`, а не копирование из образца.

## Если что-то пошло не так

**`node: command not found`**
Node не установлен или терминал открыт до установки. Закройте терминал,
откройте заново, повторите `node --version`.

**`Версия Node.js слишком старая`**
Сообщение сервиса. Выполните `nvm install 24 && nvm use 24` и повторите.
Проверить: `node --version` должно показать `v24.x.x`.

**`Не задана переменная окружения SESSION_SECRET`**
Не выполнен шаг `npm run env:init` либо он выполнялся не из папки `server`.
Убедитесь, что вы в ней: `pwd` должно оканчиваться на `/nogotochki/server`.

**`Не заданы пароли демонстрационных аккаунтов`**
Файл `.env` создан вручную из образца, а не командой: в образце значений нет,
только имена переменных. Впишите пароли сами или пересоздайте файл:
`npm run env:init -- --force`.

> **Осторожно с `--force`.** Команда генерирует новый `PASSWORD_PEPPER`,
> а на нём построены все хеши паролей в базе. После неё вход перестаёт
> работать для всех аккаунтов, включая демонстрационные, и базу нужно
> пересобрать: `npm run db:reset`. Копию прежнего `.env` команда сохраняет
> рядом, с датой в имени.

**`EADDRINUSE: address already in use :::3000`**
Порт занят — вероятно, сервис уже запущен в другом окне. Либо закройте его,
либо запустите на другом порту: `PORT=3001 npm start`.

**Проверки падают с `fetch failed` / `ECONNREFUSED`**
Сервис не запущен. `npm test` ходит по живому API, поэтому нужно два окна:
в одном `npm start`, в другом `npm test`.

**Проверки падают с `401` на демонстрационных аккаунтах**
Пароли в `.env` разошлись с теми, что записаны в базе. Так бывает, если
`.env` пересоздали после `npm run seed`. Выполните `npm run db:reset`.

**Вход отвечает `429 too_many_requests`**
Сработало ограничение частоты. Подождите столько секунд, сколько указано
в заголовке `Retry-After`, либо перезапустите сервис: счётчики живут
в памяти процесса.

**Хочу начать с чистого листа**
`npm run db:reset` — удаляет базу и собирает заново вместе с тестовыми
данными. Секреты в `.env` при этом не меняются, поэтому пароли остаются
прежними.
