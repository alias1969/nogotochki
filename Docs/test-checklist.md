# Чек-лист ручной проверки сервиса «Ноготочки»

Ручная проверка через браузер на экранах, которые уже собраны: лендинг,
вход и восстановление пароля, запись, личный кабинет клиента,
админ-панель. Кабинета мастера пока нет, поэтому отдельной части для
мастера в чек-листе нет. Учётная запись мастера встречается только
в проверках безопасности.

Откуда взяты сценарии (указано в строке «Источник» каждого сценария):

- **Паспорт, сценарий N** — сценарии использования из `CLAUDE.md`.
- **Паспорт, риск / ограничение / правило** — разделы «Ограничения
  и риски», «Роли и права доступа», «Правила записи».
- **Журнал** — то, что уже исправляли, по `Docs/development-log.md`
  (этапы) и `Docs/frontend-log.md` (раздел «Что пришлось чинить»).
  Всё исправленное проверяется повторно.
- **Код** — места, где по коду можно ожидать ошибку. В журнале их нет.

---

## Подготовка

1. Пересоберите базу, чтобы начать с одинаковых данных:
   `cd server && npm run db:reset && npm run seed`.
2. Запустите API (`npm start` в папке `server`, порт 3000) и сайт
   (`node web/serve.mjs`, порт 5173). Откройте `http://localhost:5173`.
3. Пароли демонстрационных аккаунтов лежат в `server/.env`
   (`SEED_*_PASSWORD`):

   | Роль | E-mail | Пароль из переменной |
   |---|---|---|
   | Администратор | `admin@nogotochki.local` | `SEED_ADMIN_PASSWORD` |
   | Мастер Ольга | `olga@nogotochki.local` | `SEED_MASTER_PASSWORD` |
   | Мастер Ирина | `irina@nogotochki.local` | `SEED_MASTER_PASSWORD` |
   | Клиент Анна | `anna@example.com` | `SEED_CLIENT_PASSWORD` |

4. Для сценариев с «новым клиентом» зарегистрируйте свой аккаунт,
   например `test1@example.com`, `test2@example.com`.
5. Для проверки ограничения попыток входа (Б-17) заранее поставьте
   в `server/.env` `LOGIN_MAX_ATTEMPTS=3` и перезапустите API.
   В разработке по умолчанию лимит 200 попыток, вручную до него
   не дойти. После проверки уберите строку.
6. Номера записей (`id`) для проверок с чужой записью в адресе
   берите в админ-панели на экране «Записи» или из адреса страницы
   «Запись подтверждена» (`booking-done.html?id=…`).

### Обозначения

- ✅ — обычный сценарий: всё делается правильно.
- ⚠️ — ошибочный сценарий: неверные данные, пустая форма, чужой номер,
  отказ посреди оформления и т. п.
- 👥 **Два окна** — нужны два пользователя, вошедших одновременно.
  **Окно А** — обычное окно браузера, **окно Б** — окно в режиме
  инкогнито. В каждом сценарии написано, кто входит в какое окно.

В конце каждого сценария есть строки для результата: отметьте
«Пройдено» или «Не пройдено» и запишите, что увидели на экране.

### Г-16. Календарь: прошлое, горизонт, выходные ⚠️
